# 源码与版本控制暴露验证

通过最少请求判断部署目录是否公开了不应对外提供的源码或元数据。**路径返回 200 不等于源码暴露；元数据暴露不等于完整源码或有效凭据已泄露。** 文件特征与取证限制见 [参考](reference.md)。

## 范围与准备

确认授权 origin、应用前缀、身份、请求预算、响应体上限和证据位置。公开源码仓库、刻意公开的 SourceMap 与本应私有的部署文件分别判断；不能只凭扩展名报漏洞。

默认仅匿名、串行、小样本读取候选元数据。核查 Cookie、Authorization 和代理认证，避免把管理员可见误判为公开。不得自动跟随未授权跳转、递归枚举对象库、下载数据库/完整备份或用泄露凭据登录。

## 工作流

### 1. 建立对照

在同一 origin、相同应用前缀下，记录正常首页与随机不存在路径的状态、Content-Type、重定向、正文片段。通用 HTML、登录页、WAF 挑战和自定义 404 经常也返回 200，必须与候选内容对比。

### 2. 定向探测

先根据已有线索选少量路径：

| 类型 | 最小候选 | 关注点 |
|---|---|---|
| Git | `/.git/HEAD` | `ref: refs/heads/...` 或 detached HEAD 对象名 |
| SVN | `/.svn/entries` | 老版本工作副本的结构化记录 |
| Mercurial | `/.hg/requires` | 特性标识列表；单个普通词不能确证 |
| Bazaar | `/.bzr/branch-format` | 版本控制格式标识 |
| 备份/配置 | 从部署、链接、错误信息得到的精确文件名 | 是否为非公开部署内容；不套大字典 |

路径应结合实际挂载前缀。目录本身 403/404 不代表内部文件可读或不可读；如范围允许，仅验证已列明的精确候选。

### 3. 核实格式与关联

Git HEAD 的 `ref` 应符合实际引用格式，也可能直接包含 SHA-1/SHA-256 对象名；但一段合法-looking 文本仍可能是静态示例或诱饵。需要内容类型、正常路径对照及一个范围内的最小关联元数据来支持部署关联。不要为了证明完整性拉取对象树或历史。

SVN SQLite 库、备份包和 SQL 导出可能很大且含隐私。先看响应元数据；确需内容时，须有相应许可并设客户端流式上限。可请求有限字节，但 `Range` 只是请求，服务器可能忽略，客户端仍必须在上限处断开。没有可控读取工具时标 `blocked`，不先全量下载。

只在隔离副本中离线识别文件头或结构；不 checkout、不运行仓库钩子、不加载依赖、不执行文件。禁止用发现的密钥、令牌或密码验证其他系统。

### 4. 形成结论

保留最小响应片段与哈希、完整私有证据的位置，公开报告脱敏。若意外返回秘密，停止扩大采集，按约定渠道交付并建议撤销轮换；不将原值写入公共文档或模型上下文。

- `confirmed`：已取得授权范围内本不应公开的文件/元数据，并通过格式、关联与对照排除假响应。
- `candidate`：只命中路径或文件名，尚未识别真实内容。
- `inconclusive`：响应被截断、缓存/代理混淆或部署关联未知。
- `blocked`：需要的受控读取能力或文件读取许可不足。
- `false_positive`：对照证实为同一 SPA 页面、公开样例或其他非暴露内容。
- `out_of_scope`：资产或跳转超出范围，停止主动验证。

输出包含：origin/前缀与身份、候选来源、请求和响应头、格式片段及哈希、随机路径对照、读取字节范围、实际影响和未验证项。只证明 HEAD 可读时，标题写“Git 元数据暴露”，不能写“完整源码泄露”。

## 场景自查

1. `/.git/HEAD` 返回首页 HTML，与随机路径相同：是假响应，不报源码泄露。
2. HEAD 是有效 ref，缺少部署关联：保留候选，追加一项最小关联检查。
3. 大备份对 Range 返回完整 200：在客户端上限停止，记录未完整读取，不自动解压。
4. 发现 `.env` 中疑似密钥：保留最小私有证据并停止，不尝试云账号登录。
