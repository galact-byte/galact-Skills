# hunt-idor · 越权 / IDOR / BOLA 猎杀

只解决**通过替换对象标识符或角色身份访问非授权资源一类**。核心是对每个带 ID/标识符的接口，用不同身份的凭据/不同 ID 对比响应差异。判定靠**返回了非本人资源或执行了非授权操作的客观证据**。

**国内 SRC 最高频出洞类型。** 越权是渗透测试投入产出比最高的面，优先级永远靠前。

默认只做**最小证明**：水平越权使用自己控制的两个测试账号和对象；垂直越权需有低权限身份及角色预期证据。写入或删除验证必须有对应动作许可，仅操作受控测试对象并记录清理，回滚不代替许可。方法与边界见 [参考](reference.md)。

## Scope（授权范围）

**先确认授权。**

落实：授权目标、是否有多个测试账号（至少 2 个同级 + 1 个低权限）、敏感数据类型（个人信息/订单/支付 → 高危；公开内容 → 低危）。

## Goal

系统性检测接口级访问控制：水平越权（同角色跨用户）、垂直越权（低权限访问高权限功能）、跨租户（多租户隔离失效），给出可复现的越权证据。

## Workflow

`scope-check → recon → hunt → validate → report`。

### 1. scope-check
- **动作**：准备至少 2 个测试账号的凭据（A=主账号、B=对照账号），记录各自可见资源 ID。
- **进入条件**：水平/跨租户验证具备两个受控身份及对象归属；垂直验证具备低权限身份和授权矩阵。缺少前提时记 blocked，继续其他具备条件的检查。

### 2. recon — 识别 IDOR 面
- **动作**：枚举所有带对象标识符的接口：
  - URL 路径参数：`/api/order/{id}`、`/user/{userId}/profile`
  - Query 参数：`?id=123&userId=456`
  - Body 参数：`{"orderId": 789}`
  - GraphQL 参数：`query { user(id: "xxx") { ... } }`
- **信号识别**：
  - 数字自增 ID → 高优先（可枚举）
  - UUID → 中优先（需要泄露点配合）
  - 接口返回他人可见资源列表 → 信息泄露型
- **输出**：候选接口清单 + ID 类型 + 操作类型（读/写/删）。
- **终止条件**：至少 1 个候选接口。

### 3. hunt — 三维测试
- **动作**：对每个候选接口做三维越权测试：

#### 3a. 水平越权（BOLA）
- 用 A 的凭据 + B 的资源 ID → 看能否读到 B 的数据
- 用 B 的凭据 + A 的资源 ID → 反向验证
- 对照：用 A 的凭据 + A 的资源 ID → 正常返回

#### 3b. 垂直越权（BFLA）
- 用低权限账号的凭据调用管理接口
- 枚举管理接口来源：前端 JS 路由、API 文档、目录爆破、错误响应泄露

#### 3c. 跨租户（多租户场景）
- 用租户 A 的凭据 + 租户 B 的资源 ID

- **关键判定**：
  - 只有在对象归属、预期权限、实际响应语义及对照都明确时，才确认越权。
  - 401/403、空响应、自己的数据或通用数据都需核实业务含义；状态码不能单独确认或证伪。
  - 缺少身份或对象归属证据时记 inconclusive，不把未知当作误报。

### 4. validate → report
- **动作**：逐项核对下列证据门槛，保存私有请求响应，公开截图脱敏。未满足时区分缺前提、证据不足与已证伪。
- **输出**：confirmed / inconclusive / blocked / false_positive / out_of_scope；兼容旧 killed 记录时，仅用于有对照证伪的候选。

## 7-Question Gate（证据不足不确认）

1. 目标在**授权 scope** 内？
2. 返回的数据确实**属于其他用户/非授权角色**（非公开数据、非自己的数据做了 ID 替换）？
3. 越权是**接口级缺陷**（非前端隐藏，后端确实缺校验）？
4. **可复现**（稳定返回他人数据，非缓存/CDN 残留）？
5. 对比了**正常请求 vs 越权请求**，差异明确？
6. 已私有保存**正常与越权请求响应**，公开材料脱敏 Header 中的凭据？
7. **未对他人数据做修改/删除**（写越权用自己的测试数据验证）？

## 高频 IDOR 点速查（进站先过一遍）

| 功能 | 典型接口 | 预期危害 |
|------|----------|----------|
| 个人信息/资料 | `/api/user/{id}` | 读取他人手机/身份证/地址 |
| 订单详情 | `/api/order/{orderId}` | 读取他人订单（含金额/商品/地址） |
| 消息/通知 | `/api/message/{id}` | 读取他人站内信 |
| 文件/附件 | `/api/file/{fileId}` | 下载他人上传的文件 |
| 评论/反馈 | `/api/comment/{id}` | 修改/删除他人评论 |
| 收货地址 | `/api/address/{id}` | 读取/修改他人地址 |
| 权限管理 | `/api/role/assign` | 给自己提权 |
| 组织/团队 | `/api/org/{orgId}/members` | 跨租户枚举成员 |

## 与其他 hunt skill 的链

- IDOR + `hunt-race-condition`：并发创建 → IDOR 读取 → 读到他人刚创建的资源
- IDOR + 信息泄露：接口返回多余字段（手机/邮箱/ID）→ 用 ID 进一步越权
- IDOR + `hunt-auth-bypass`：认证绕过获取任意身份 → 直接越权
- IDOR + `hunt-logic`：篡改他人订单价格/状态

## Finding 输出格式

```
### <Title>
- Severity: Critical | High | Medium | Low
- Asset: <接口 + 参数 + 越权类型>
- Reproduction: <A 凭据 + B 的 ID → 返回 B 的数据>
- Impact: <泄露的数据类型与敏感度>
- Evidence: <evidence/ 两组请求响应截图对比>
- Status: confirmed | inconclusive | blocked | false_positive | out_of_scope
```
