# 子域接管验证

目标是判断授权域名是否仍指向失效资源，以及第三方能否控制该域名的内容。**DNS 悬挂、资源名可创建、自定义域名能绑定是不同事实**，逐项取证。厂商指纹与确认条件见 [参考](reference.md)。

## 适用与边界

- 处理 CNAME、失效托管资源及子区 NS 委派；普通开放重定向、Host 头反射不属于本类。
- 先确认域名、端口、DNS 查询与 HTTP 验证的范围。DNS 指向第三方不等于获准扫描第三方资产。
- 默认只查询 DNS、访问授权域名并检查官方规则。记录查询时间、解析器、TTL、完整记录链与响应。
- 注册资源、绑定客户域名、修改 DNS、上传证明页面、申请证书均有外部副作用，必须有相应明确许可；未获准时停在 `candidate` 或 `blocked`。
- 不注册过期 NS 域名、不修改 MX、不接收真实邮件、不索取访客 Cookie 或令牌。

## 工作流

### 1. 建立候选

复用已获准的子域清单，检查精确主机的 CNAME/A/AAAA/NS；不要自动扩大到整个关联组织。记录每跳 DNS 名称并区分 NXDOMAIN、NODATA、SERVFAIL 和超时。后两者不能说明资源可注册。

可在已安装 DNS 工具中查询，例如 Windows：

```powershell
Resolve-DnsName -Name app.example.com -Type CNAME
Resolve-DnsName -Name app.example.com -Type NS
```

命令中的域名是占位符，运行前换成当前批准的主机；没有工具时使用现有 DNS 客户端，不自行安装。

### 2. 核实 HTTP 与服务商

在正确 Host/SNI 下访问授权域名，保留状态、响应头、正文最小片段和 TLS 结果。不要用服务商主页替代原主机响应，不跳转到未授权主机。比较不存在路径、已知正常页面和解析结果，排除统一 CDN/WAF 错误及缓存。

### 3. 检查认领条件

对照该服务商当前官方域名验证、资源名称保留、地区及账号限制。资源名看似空闲、404、`NoSuchBucket`、Pages 错误都只是候选信号。GitHub 域名验证、Azure 域名验证令牌或名称保留可能阻断接管；查不到公开 TXT 也不能推断没有后台保护。

记录官方 URL、核实日期、该候选的匹配条件与尚缺前提。历史指纹库只辅助定位服务商，不代替当前事实。

### 4. 最小确认

仅在已批准的隔离资源和域名上绑定并放置随机纯文本标记，避免脚本、认证表单和第三方内容。通过**原授权域名**读到自己生成的标记，结合资源归属与绑定证据，才能确认内容控制。仅通过云厂商 URL 访问标记不足以确认原域名可接管。

登记新增资源、费用条件、绑定与清理责任；按预先同意的顺序解除绑定和删除测试资源，保留复核证据。没有动作许可则提交悬挂证据及限制，不为了补齐结论实际抢占。

## 判定与输出

- `candidate`：悬挂记录或厂商指纹，但可认领性未知。
- `confirmed`：范围与动作获准、绑定归属明确、原域名返回受控标记，且排除了既有站点/缓存。
- `inconclusive`：DNS 或 HTTP 结果矛盾、传播未稳定、实际保护状态不明。
- `blocked`：缺少资源注册/绑定许可、测试账号或必要条件。
- `false_positive`：有证据证明资源仍属正常服务或已被保护；结论限定于已核实条件。
- `out_of_scope`：不在范围内，停止主动请求。

每条记录包含：资产与范围依据、DNS 链/TTL/时间、Host/SNI、HTTP 片段、厂商规则与日期、资源归属、受控标记（如已批准）、结论/限制和清理状态。NS 悬挂与邮件相关风险分别记录，不从普通 CNAME 推断全区或邮件控制。严重度依实际可控内容与信任关系评定，不默认 Critical。

## 场景自查

1. Pages 默认 404，但域名验证状态未知：保留候选，不确认接管。
2. 原域名读到受控标记，只有云厂商 URL 的截图缺失：补原域名请求证据，不能互相替代。
3. CNAME 目标 NXDOMAIN，禁止注册资源：记录悬挂与 `blocked`，不创建云资源。
4. NS 查询 SERVFAIL：检查解析与委派证据，不判为域名可注册。
