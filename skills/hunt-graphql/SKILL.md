# GraphQL 安全验证

围绕 GraphQL 的解析、执行与业务权限检查，找到可复现的边界差异。**能查询 schema、接受 alias、返回 HTTP 200 都不能单独证明漏洞。** 协议区别、示例与官方依据见 [参考](reference.md)。

## 前提与预算

记录端点、环境、允许的账号/租户、测试对象、可用操作、业务限制、请求及操作预算、响应大小与停止条件。预算同时计算 HTTP 请求数、实际 resolver/业务动作数和订阅持续时间；一个请求不等于一次业务动作。

优先使用两个自有测试账号及各自对象，默认只读。mutation、登录/验证码、收费动作、深度/宽度/大分页测试、订阅与并发都需在当前授权中明确允许；不通过压力、爆破或访问真实用户数据补证。现场没有可用测试对象/观测数据时保留未定状态。

## 流程

### 1. 从实际请求还原执行面

复用浏览器流量、客户端源码或已授权 schema，记录 URL、HTTP 方法、Content-Type、身份、`query`、`variables`、`operationName`、`extensions`。只在有端点线索时发送最小只读查询，例如 `{ __typename }`；不要扫一长串猜测路径。

区分三个概念：alias 是同一 operation 的多个响应字段；一个文档可定义多个 operation，但应由 `operationName` 选择一个执行；JSON 数组 HTTP 批处理是具体服务端能力，不是所有 GraphQL 服务都支持。它们不能互相替代作为绕过证据。

### 2. 最小化发现 schema

按需读取根查询与目标类型字段，避免默认导出整份 schema。禁用 introspection 时改用已有客户端查询或正式文档，不自动爆破字段。记录字段类型、参数、嵌套关系、身份要求、可能的副作用；`query` 名称不保证实现完全只读。

introspection、GraphiQL、字段名建议仅说明可发现性；只有实际暴露越出约定边界的敏感信息或能力时，才按证据确认影响。停用 introspection 也不等于访问控制正常。

### 3. 分离对象、字段和动作授权

建立对照：A 访问 A 的测试对象成功；B 访问 B 的测试对象成功；随后用 B 身份访问 A 的已知测试对象，仅选择证明归属的最小字段。分别检查根字段、嵌套关系、`node` 类直达入口，以及普通字段与受限字段。公开字段能读，不代表整个对象越权。

一次只改身份、对象或字段中的一个。REST 拒绝但 GraphQL 成功只是线索，要核实两者预期权限、对象和字段相同。mutation 只在许可下使用可还原的测试动作，并从状态读回确认；`data`、`errors`、HTTP 状态一起解释，不能把错误文本或空对象写成成功越权。

### 4. 有限验证批量与业务限制

确认现场确有业务限制，记录计数单位、窗口、测试身份与可观察结果；用预先约定的小样本对照单操作、少量 alias 或受支持的 JSON 批处理。统计实际动作/结果，不只统计响应条数。没有业务限制与反例时，只记录能力支持。

不要用登录、OTP、支付或真实账号做默认限流探针。没有安全小样本可测时，通过授权的配置、代码与日志检查计数位置；无法获得证据标 `inconclusive`。不能因为两次只读查询成功就推断可爆破或无上限。

### 5. 资源、输入与订阅边界

复杂度、分页、超时等优先查配置和日志；仅在允许的测试环境与预算内做有界差异，不构造递归展开、超大整数、海量 alias 或耗尽服务的查询。一次慢响应不能确认 DoS；延迟、错误率或资源占用异常立即停止。

参数进入数据库、URL 或模板的线索可交给现场已有专项 Skill；本 Skill 本身不升级攻击动作。持久化查询区分缓存/APQ 与明确配置的 operation allowlist，不能把 APQ 首次接受完整查询写成白名单绕过。存在订阅时另核实连接身份、订阅对象、事件权限、注销后行为和取消订阅；只连接自有测试流，结束后释放连接。

## 结论与证据

使用 `candidate`、`confirmed`、`inconclusive`、`blocked`、`false_positive`、`out_of_scope`；缺许可不是误报，未测不写安全。

记录端点、身份角色、测试对象归属、operation/variables（脱敏）、基线与对照、预期业务规则、实际 `data/errors`、动作计数、窗口、预算和已验证影响。schema/日志等敏感证据私有保存，不公开 Cookie、Token 或整份业务数据。

## 场景自查

- 仅开放 introspection：记录发现面，不确认越权或敏感数据泄露。
- HTTP 200 但 `errors` 为拒绝访问、`data` 为 null：该次请求没有成功证明越权。
- 两个 alias 返回两份公开数据：正常能力，缺少业务限制反例不能称限流绕过。
- 只能靠巨大查询证明影响：停在候选，另行安排获准的隔离环境验证。
