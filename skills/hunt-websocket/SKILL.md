# WebSocket 安全验证

把连接看成有身份与生命周期的业务会话，分别核实握手、认证、每条动作及订阅的权限。**握手成功不等于认证成功；能伪造 Origin 不等于浏览器可跨站劫持。** 协议区别与官方依据见 [参考](reference.md)。

## 前提与边界

记录端点、环境、允许的测试账号/房间/对象、浏览器、连接与消息预算、观察窗口、允许写入动作及证据位置。默认使用自有测试账号与数据，低速、少连接、只读；不能自动压测、广播消息、加入真实用户频道或重放资金/通知动作。

先使用已有浏览器流量或代理记录。工具缺失时记录 `blocked`，不猜 MCP 参数，不自动安装客户端。消息、URL、日志中的 Token 与 Cookie 脱敏；实验结束取消订阅、关闭本轮连接并清理获准的测试数据。

## 流程

### 1. 还原协议和正常行为

从实际流量记录 URL、TLS、握手 Origin、Cookie/Token、子协议、首条认证消息、订阅/操作格式、关联 ID、正常响应与关闭事件。HTTP/1.1 Upgrade 常见为 101，但现代传输可能采用其他机制；按现场协议解释，不能只靠状态码识别。

Socket.IO/Engine.IO、STOMP、GraphQL 订阅有各自握手、心跳和消息封装，不把任意 JSON 当作等价业务消息。先完成一次正常自有测试流，再改变一个变量。

### 2. 区分连接与认证

对比正常身份、缺少身份和失效测试身份。允许匿名建连后首条消息认证可以是正常设计；关键是认证前能否读到或执行受保护能力、认证失败/超时后连接如何处理。

Origin 用于浏览器来源校验，不是用户身份。CLI 可更改 Origin 只说明服务器来源策略；复制 Cookie/Token 到 CLI 会人为加入身份，不能据此确认 CSWSH。

### 3. 在真实浏览器核实 CSWSH

只在已获准的自有测试页面与测试账号上检查。使用实际不同源、必要时不同站点的页面发起连接，记录浏览器真实发送的 Origin 和身份、服务器接受结果、受保护消息是否可读或动作是否成功。

Cookie 是否携带取决于 SameSite、Secure、Domain/Path、浏览器第三方 Cookie 策略等；跨源不等于跨站。不能手动补 Cookie、额外注入受害者 Token 或关闭浏览器保护来替代真实条件。

只有普通跨站页面能借测试账号的实际身份，读取受限消息或执行获准的受保护测试动作，才按已证实能力报告 CSWSH。Origin 未校验、连接成功、公共消息回显或只能 CLI 重现时，保留配置线索，不提升为劫持。失败时记录是身份未携带、来源被拒、认证未完成还是其他原因。

### 4. 检查消息与订阅授权

用 A、B 两个自有账号和各自对象建立正常对照。在 B 的正常连接中只改 A 的已知测试房间/对象/订阅 ID，检查加入、读取、订阅以及获准动作。分别判断对象、租户、字段与动作权限；不能因连接已认证而省略消息级判断。

服务端响应“accepted”或回显本地发送内容不证明数据已写入；以独立读取或另一自有客户端观察结果。接收方订阅是否在建立时及后续事件发布时正确鉴权也要分别记录。没有测试数据或权限规则时不接入真实用户流。

### 5. 检查会话与连接生命周期

在约定窗口内，保持一个已有测试连接，然后主动注销、等待测试 Token 过期或由授权操作撤销测试身份；分别观察既有连接、后续消息、重连、重新订阅。确认撤销在 HTTP 基线已生效，区分在途消息、缓存数据、宽限策略与撤销后新发生的受保护行为。

连接暂未断开不等于授权仍有效。只有撤销后仍取得不应有的新数据/动作，且违反明确会话策略时，确认相应缺口。没有获准撤销操作或观察窗口不足时记 `blocked`/`inconclusive`。

### 6. 输入与资源边界

在正常消息模板上用小型、无害标记检查格式、类型、长度和未知动作处理；注入线索交给现场已有对应专项流程，不自动堆载荷。连接数、心跳、消息大小、速率、压缩与背压先审配置/日志；洪泛、巨大帧、压缩炸弹和耗尽连接不是默认验证手段。

## 状态与交付

使用 `candidate`、`confirmed`、`inconclusive`、`blocked`、`false_positive`、`out_of_scope`。区分配置观察、跨站可达性、身份、消息权限与实际业务影响，缺少证据不写已证伪。

记录正常与对照握手、真实浏览器/页面源、身份携带条件、子协议与消息方向、UTC 时间、连接/消息关联 ID、对象归属、业务结果、撤销窗口、关闭/清理结果及未验证项。原始敏感帧私有保存，报告只展示证明所需字段。

## 场景自查

- CLI 改 Origin 并手动带 Cookie 后连接成功：来源策略线索，不能直接确认 CSWSH。
- 浏览器跨站连接成功但只收到公开欢迎信息：未证明受保护能力被劫持。
- 注销后 socket 仍 open、后续受保护动作被拒：不能只靠连接状态确认注销失效。
- B 收到自己的消息回显：先核实广播/持久化与对象归属，不当作越权写入。
