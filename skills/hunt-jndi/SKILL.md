# JNDI 注入验证

目标是确定可控输入是否进入 JNDI 命名查询，以及该查询在实际运行时能产生什么影响。**Java 技术栈、旧版本号、OAST 回调、反序列化、代码执行分别取证**，不能自动跨层推导。运行时条件见 [参考](reference.md)。

## 授权与前提

先记录目标、入口、账号、请求预算、回调端点与协议、观察窗口、允许动作、证据位置。回调只能使用已批准的测试设施，不发送业务数据到未经同意的第三方平台。

默认只做唯一随机标记的命名查询验证；接收端不得返回远程类、序列化对象、对象工厂或执行命令。现有监听器若不能确认上述行为，标 `blocked`，不要直接启动利用框架。

禁止把环境变量、主机名、凭据或云密钥拼进回调名。命令执行、反序列化利用及写入都需要对应明确授权，本 Skill 不将它们作为自动升级步骤。

## 工作流

### 1. 定位真实输入链

复用现有请求、日志或源代码线索：直接 `InitialContext.lookup` 参数、管理数据源配置、日志消息/上下文字段。管理配置保存可能有持久副作用，未经许可不修改。

Log4j 是一条特定触发链：只有可控输入到达相关且可触发的 `log4j-core` 路径时才有相应风险。仅存在 `log4j-api`、Java 指纹或反射字符串不能确认 Log4Shell。通用 JNDI 与 Java 反序列化不是同一分类。

### 2. 建立基线与控制

为每个入口与请求生成不同随机标记，记录发送时间、参数位置、接收端日志和观察窗口。先验证回调设施在自有环境中正常；自测标记必须与目标标记分开，避免把本机解析当成目标回调。

基线采用普通随机文本，测试只改变一个字段，阴性对照使用不含 lookup 语法的同类字符串。不要把一个标记同时塞进所有 Header，也不要展开盲目载荷矩阵。

### 3. 最小探针

对已明确的直接 lookup 参数，在许可范围内使用受控命名端点；日志 lookup 的示意形式为：

```text
${jndi:ldap://<唯一随机标记>.<已批准的回调域>/probe}
```

这是占位示意，不能原样发送。接收端只记录查询并返回空/未找到结果，不提供 Java 对象。若仅允许 DNS 观察，保留 DNS 层证据，不将其升级为 LDAP 成功、JNDI 确认或代码执行。

按已约定小样本与窗口观察，超时记 `inconclusive`；无回调可能来自入口未触达、异步日志、出网限制、修复或接收端故障，不能直接写“安全”。出现服务异常、延迟恶化或意外状态变化立即停止该方向。

### 4. 归因与分层结论

核对唯一标记、协议、时间、正反对照，以及日志/调用栈或其他能够归因到目标的证据。安全网关、预览器、扫描沙箱、代理和递归解析器可能代为解析；源 IP 不一定是目标 JVM。

- 只有 DNS 回调：记录目标相关出网线索；缺少链路归因时仍为 `candidate`/`inconclusive`。
- 证实可控输入触发目标 JNDI 命名查询：可确认 **JNDI lookup 注入**，同时注明尚未证明代码执行。
- 只有具体 Log4j 版本或依赖扫描告警：记组件风险线索，不写已触发 Log4Shell。
- RCE 只在独立、获准的执行验证已有直接证据时另行表述；本流程不自动生成执行证据。

## 状态与交付

状态使用 `candidate`、`confirmed`、`inconclusive`、`blocked`、`false_positive`、`out_of_scope`。证据不足不是误报；只有对照证伪时写 `false_positive`。严重度与确认层级、可控范围和实际影响一致。

每条记录包含：入口/字段、当前范围、基线与探针请求、随机标记、UTC 时间/观察窗口、回调协议与原始记录、对照、归因、Log4j/JDK/组件与配置（已知或未知）、确认层级、未验证影响。敏感原文私有保存，公开报告不含 Cookie 或凭据。

## 场景自查

1. 只有 DNS 回调且来源像安全网关：排查代解析，不确认 JVM lookup 或 RCE。
2. 同一标记被多个 Header 使用：无法归因单个入口，使用新标记做小样本对照。
3. JDK 较新但记录了 LDAP 查询：报告实际查询；不套“高版本必安全”或“有回调必 RCE”。
4. 回调域不可用或不获准使用：标 `blocked`，不擅自更换第三方平台。
