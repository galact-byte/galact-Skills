# 竞态验证参考

## 选择最小可比实验

| 候选 | 串行对照 | 并发观察 | 需排除 |
|---|---|---|---|
| 限领一次 | 连续两次仅一次产生领取记录 | 两个请求是否产生不同、有效领取记录 | 同一记录重复返回、缓存 |
| 一次性 token | 首次使用后再次拒绝 | 是否产生超出规则的独立有效结果 | 多个响应引用同一结果、异步撤销 |
| 库存/余额 | 在测试沙箱内按规则扣减 | 最终账本与库存是否违反约定 | 预授权、排队、最终一致性 |
| 状态机 | 不允许跳过或重复状态转换 | 两条路径是否组合出非法终态 | 前端展示延迟、补偿事务 |

除并发时序外保持身份、对象类型和参数可比。相同对象不可重置时，使用具有相同可验证初态的独立受控副本；做不到就说明限制。每个请求保存幂等键、业务 ID 及最终状态，不能只数 200。

## 工具与协议

- [Burp Repeater：发送请求组](https://portswigger.net/burp/documentation/desktop/tools/repeater/send-group)：核对当前版本支持的顺序/并行发送和连接限制。
- [PortSwigger Web Security Academy：竞态条件](https://portswigger.net/web-security/race-conditions)：业务不变量、隐藏子状态与同步方法的背景。
- [Turbo Intruder 官方仓库](https://github.com/PortSwigger/turbo-intruder)：工具独立于本仓库；使用前核对当前 README 与示例，并取得安装许可（若尚未安装）。

本库不提供可执行并发脚本，也不将某个工具的示例当作通用跨版本接口。没有工具时可用现有客户端做小组并发，但需写明未做网络级同步；未复现不能反证漏洞不存在。

请求组并行、线程并发、HTTP/1.1 最后字节同步、HTTP/2 单包攻击是不同方法。代理、TLS、HTTP/2 流控、连接重建和服务器处理方式都会影响时序。记录实际协议与方法，不仅写“单包”。

## 停止与清理

预先约定总请求数、每组并发、组间观察时间、最大延迟与业务异常停止条件。限流或故障出现后不自行提升强度。对沙箱外的扣费/退款、库存和通知操作单独确认许可。

记录每个测试对象的原态、变更、责任人与清理结果。不能安全清理时停止并交给约定负责人，不为了回滚再发高风险操作。响应相同而最终业务状态未知时，结论为 `inconclusive`，不是 `confirmed` 或安全。
