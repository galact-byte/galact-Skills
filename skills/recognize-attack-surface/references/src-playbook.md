# src-playbook · SRC 高频类打法（模块参考）

`patterns.md` 是**案例索引**（研判某类横切时读）；本文是**可照做的打法参考**。以下类别已有专用 hunt skill，本文做补充参考而非主流程：

| 类别 | 专用 hunt skill | 本文角色 |
|---|---|---|
| 越权/IDOR | `hunt-idor` | 补充 payload |
| 文件上传 | `hunt-file-upload` | 补充绕过技巧 |
| SSTI | `hunt-ssti` | 补充引擎判断 |
| 支付/业务逻辑 | `hunt-logic` + `hunt-race-condition` | 补充场景 |
| OAuth/JWT | `hunt-oauth-jwt` | 补充场景 |
| LFI/文件包含 | `hunt-path-traversal` | 补充 payload |
| GraphQL | `hunt-graphql` | 主流程见专用 Skill |
| WebSocket/实时订阅 | `hunt-websocket` | 主流程见专用 Skill |

仍缺专用 hunt skill 的类别：短信/频率、CRLF、Host 头注入、WAF 绕过。这些类别打法仍以本文为主。研判仍走 SKILL.md 的 7 问纪律，只做只读最小证明。

## 黑盒 Web 侦察顺序（吸收自 pentestagent web playbook）

`指纹/框架 → 认证入口 → 功能点分类 → 输入面枚举 → 按影响×可达性排序`：
1. 先定**框架/中间件/语言**（决定专项：Shiro/Struts/ThinkPHP/Spring/FastJson…）。
2. 标**信任边界**：未认证↔认证、普通↔管理、租户 A↔B、Web↔API↔小程序。
3. 把功能点归类：**取数据**（列表/详情/导出）、**改状态**（下单/支付/改料）、**发消息**（短信/邮件）、**传文件**（上传/导入）。
4. 每类套下面对应打法，先测"最高影响 + 最省前置条件"的。

## 1. 越权 / IDOR（SRC 头号高频）

**信号**：URL/参数/body 里有 `id`/`order_id`/`user_id`/`uid`/`org_id`/`file_id`；管理接口 `/admin/*`。
**打法**（只读证明，拿到他人非敏感字段即停）：
- 水平：登录 A 拿对象 ID → 换 **B 的 Cookie/Token** 访问同 ID → 能读/改 = 水平越权。
- 垂直：普通用户 Token 访问 `/api/admin/*`、管理动作接口 → 返回 200+数据 = 垂直越权。
- 遍历：ID 自增/可猜 → 小范围 ±1/±2 探测（**不批量拉库**），证明可枚举即止。
- 无鉴权：直接去 Cookie 访问需登录接口 → 仍返回数据 = 未授权访问。
**证据**：两账号/两身份同请求的响应差；脱敏截图。**红线**：只取"证明属于他人"的最小字段，不导出他人隐私。

## 2. 文件上传

**信号**：头像/附件/导入/富文本图片/工单。
**打法**：后缀绕过（`.php.`/`.pHp`/`.php5`/`.phtml`/双扩展/`.htaccess`）、MIME 改 `Content-Type`、magic bytes 伪装、`%00`/换行截断、`Content-Disposition` filename 注入、解析器差异（IIS/Nginx 解析漏洞）、条件竞争（上传瞬间访问）。
**证明**：上传后**能解析执行**才算 RCE（拿 `id`/`whoami` 回显即停，不留 webshell、传完即删）；仅能上传但不可执行 → 降级为"任意文件上传/存储"。

## 3. SSTI（模板注入）

**信号**：用户输入进模板渲染——站内信/邮件模板、报表、导出、错误页回显。
**探针**：`${7*7}` / `{{7*7}}` / `<%= 7*7 %>` / `#{7*7}` → 回显 `49` 定位引擎。
- Jinja2/Twig `{{7*7}}`、FreeMarker `${7*7}`、Velocity `#set`、Smarty `{7*7}`、ERB `<%= %>`。
**证明**：算术回显 = 确认；进一步只取引擎版本/沙箱边界证明，**不直接打 RCE 命令**（高危先停确认）。

## 4. LFI / 文件包含 / 路径读取

**信号**：`file=`/`path=`/`template=`/`page=`/`include=`/下载接口。
**打法**：`../../../../etc/passwd`、`....//`、编码 `%2e%2e%2f`、`php://filter/convert.base64-encode/resource=`、`/proc/self/environ`、Windows `..\..\win.ini`。
**证明**：读到 `/etc/passwd` 或 `win.ini` 或源码 base64 即止；**不读密钥/凭据实体**，证到"可读任意文件"即够。（与 `hunt-path-traversal` 有交叠时优先用该 skill。）

## 5. 支付 / 业务逻辑

**信号**：下单/支付/退款/优惠券/积分/提现。
**打法**：改 `price`/`amount`/`total`/`quantity`（含**负数**）、币种混淆、四舍五入套利、跳步（`step=1→3`）、重放订单、并发竞态（优惠券/秒杀超卖）、退款金额篡改、支付回调 `status` 伪造。
**证明**：构造出**违反不变量的稳定结果**（少付/多得/负余额）在**测试账户**内复现；不实际造成资金损失，拿到状态即停。详细不变量清单见 `patterns.md` B 段。

## 6. 短信 / 邮件 / 验证码频率

**信号**：`/sms/send`、`/captcha`、登录/注册/找回验证码。
**打法**：同号高频重放测**无频率限制**（轰炸）；6 位数字验证码 + 无锁定 → 证明**可爆破**（小样本证明空间可枚举，**不实际轰炸真实号/不爆破真实账户**）；验证码发 phoneA 提交改 phoneB 测**归属校验缺失**。
**证明**：连续 N 次成功发送/无锁定的响应即证；点到为止，避免骚扰真实用户。

## 7. 其余 Web 类快查（SecSkills 提炼，低频但要会认）

- **GraphQL**：优先使用 `hunt-graphql`；schema 可发现性、批量能力与越权/限流影响分别取证，不用深递归或大规模枚举做默认验证。
- **CRLF**：`%0d%0a` 注入响应头 → set-cookie/重定向注入/缓存投毒前置。
- **Host 头注入**：改 `Host`/`X-Forwarded-Host` → 密码重置链接投毒、缓存投毒、内网 SSRF 前置。
- **WAF 绕过**：编码/大小写/分块/HPP/注释，绕不过就换注入点，别死磕。

## 纪律回顾

授权内、只读最小证明、拿到客观信号（差异/回显/时延/越权数据）即止，高危（RCE/SSTI 命令/资金）先停确认再深入。所有证据脱敏。
