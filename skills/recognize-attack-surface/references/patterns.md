# recognize-attack-surface · 信号目录与真实案例

四类横切问题的识别信号 + 本仓库第二轮高价值案例（value_score≥8）。研判某类时读对应段。

## A. 跨组件攻击链

**识别信号**：多入口/多端（Web+移动+API）、多信任边界、单点看着"不够狠"但能拼。

**串链方向**：信息泄露 → 凭据 → 绕认证 → 越权/IDOR → 提权 → 执行/读密/云接管。

**真实案例**
- #1567186 Apple 登录 one-click 接管：OAuth response_type/mode 篡改 + 页面 XSS 从 fragment 偷 token（认证↔前端跨界）。
- #134321 Algolia RCE：GitHub 泄露 secret → 签名恶意 cookie → Ruby 反序列化 RCE（信息泄露→反序列化）。
- #493324 GitLab 提权到任意用户：会话类型混淆跨组件。
- #412021 ImageTragick：上传→ImageMagick delegate→读文件外带（上传↔解析器↔SSRF）。
- #1238017 AWS LB Controller：SG ID 字典序被冒充（云控制平面逻辑）。
- #1806939 URN 注入导出全库邮箱（对象引用↔批量）。
> 打法：每拿到一个"半成品"就回看路由表，问"它能接到哪个 hunt skill 的入口/输出上"。

## B. 业务逻辑漏洞

**识别信号**：涉及金额/配额/所有权/状态机/时序的多步流程；后端信任前端传来的状态。

**常见不变量与打破手法**
- 金额守恒 → 负数量/负价格/超额退款/币种混淆（#379049 门罗钱包报告收到两次）。
- 每人一次 → 竞态并发领取（see 也可配 hunt 里的竞态思路）。
- 只能改自己 → IDOR / 越权对象。
- 状态单向 → 跳步/重放/乱序（#1330529 OTP 抢注不存在餐厅的 listing）。
- 身份唯一 → 邮箱规范化/预验证绕过（#565883 SCIM 预验证进内部）。
- 运行身份 → 以任意用户跑流水线作业（#894569）。
- 位置/隐私推断（#1234406 精确到 5m 的位置外泄）。

**真实案例**：565883 / 1330529 / 379049 / 894569 / 1234406 / 889886（多步串联 CTF）。

## C. 安全配置错误

**识别信号**："默认就危险"、"本不该暴露"。

**清单 + 案例**
- 悬空资源接管：未认领 S3 桶/子域（#399166 劫持 S3 桶 RCE）。
- 邮件/域配置：Mailgun 误配可嗅探邮件与 postmaster（#174983）。
- 不安全默认：curl `-K` 配置读失败仍继续不安全连接（#1542881）、Windows 路径默认不安全 CVE-2019-1552（#683318）。
- 容器/编排：worker 容器逃逸读宿主文件（#694181）、kOps GCE 提权（#1842829）、ingress-nginx 取 service account（#1382919）。
- 凭据存储：生物密钥存 Windows Credential Manager 可被访问（#1874155）。
> 研判：先指出"哪个开关/默认错了"，再证到"能读到/能越权到什么"。

## D. 信息泄露

**识别信号**：报错/调试/源码/密钥暴露；响应差异构成侧信道；能读他人/跨租户数据。

**清单 + 案例**
- 侧信道：CSP report-uri 泄露断言（#16910）、时间/长度差。
- 越权读：ContentProvider 组合读私有数据（#534541）、受保护推文经 URL 暴露（#491473）。
- 客户端泄露：密码管理器允许网站读用户数据（#430854）。
- 内存型：I2P C++ heartbleed 式泄露（#295740）、序列化到本地文件读到 Papertrail（#416123）。
> 研判：拿到数据后立刻回到 A，问"它是哪条链的第一环"。

## 用法回顾

1. 侦察出信号 → 路由表选 hunt skill（多命中按影响×可达性排序）。
2. 没有专用 skill 的 → 用 A/B/C/D 的不变量/清单研判。
3. 每个"半成品"都尝试接进跨组件链（A）。
4. 全程按 SKILL.md 的 7 问纪律，只在授权内、用证据说话。
