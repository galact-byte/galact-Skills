# hunt-logic · 业务逻辑猎杀

只解决**业务规则/流程/状态机的逻辑缺陷一类**（非技术注入，而是业务上"不应该能做到但做到了"）。核心是理解业务规则，然后构造违反规则的操作序列。判定靠**实际业务状态的异常变化**（少付了钱、多得了东西、跳过了必要步骤）。

业务逻辑验证先明确具体规则和后端状态。只在获准的沙箱、测试账号与测试对象上做最小证明，确认后停止；小金额和可回滚都不能替代付款、退款、审批等动作许可。检查方法见 [参考](reference.md)。

## Scope（授权范围）

**先确认授权。**

落实：授权目标、受控账号/对象、沙箱、支付/退款/审批等具体动作许可与清理方式。小金额不自动构成许可；**未确认不动金额。**

## Goal

系统性识别业务规则漏洞：金额/数量篡改、流程跳步、状态机违规转换、策略叠加滥用，给出可复现 PoC 和实际影响量化。

## Workflow

`scope-check → recon → hunt → validate → report`。

### 1. scope-check
- **动作**：确认授权、测试账号、金额操作许可。
- **终止条件**：scope 明确。

### 2. recon — 业务流程画图
- **动作**：走通完整业务流程，记录每个步骤的接口和参数：
  - 电商：浏览→加购→结算→支付→发货→收货→退款
  - SaaS：注册→试用→付费→升级→到期→续费
  - 审批：提交→审核→批准→执行→归档
- **重点关注**：
  - 价格/金额在哪一步确定（前端传 vs 后端算）
  - 数量/折扣在哪一步校验
  - 状态在哪一步转换、能否回退
  - 有没有多步操作间的一致性检查
- **输出**：业务流程图 + 检查点清单。

### 3. hunt — 按面攻击

#### 3a. 金额/价格篡改
- 修改请求中的 `price`/`amount`/`total` 为 0、负数、极小值（0.01）
- 修改 `discount`/`couponAmount` 超过商品价格
- 币种篡改（如果支持多币种）

#### 3b. 数量操控
- 负数数量：`quantity: -1`（可能导致退款/余额增加）
- 零数量下单（可能跳过支付）
- 超大数量（整数溢出）

#### 3c. 流程跳步
- 直接调用支付成功回调而不实际支付
- 跳过验证步骤直接调最终确认接口
- 修改订单状态为"已支付"/"已审批"

#### 3d. 优惠/积分滥用
- 同一优惠券对同一订单重复应用
- 多张优惠券叠加超过商品价格（总价为负？）
- 积分兑换后取消订单、积分不扣回
- 新用户优惠在老用户接口使用

#### 3e. 状态机违规
- 已完成订单再次修改/取消
- 已退款订单再次退款
- 审批流中越级操作

### 4. validate → report
- **动作**：逐项核对证据门槛；缺许可/账号记 blocked，规则或状态不明记 inconclusive，有对照证伪才记 false_positive。
- **关键**：严重度按实际可达影响评定，不把显示异常、理论金额或沙箱状态直接写成真实资损。

## 7-Question Gate（证据不足不确认）

1. 目标在**授权 scope** 内？
2. 操作确实**违反了业务预期规则**（不是正常功能的合法使用）？
3. 有**客观的异常状态**（支付金额不符/订单状态异常/余额不一致），非显示 bug？
4. **后端确实执行了异常操作**（不是仅前端显示异常、后端仍正确处理）？
5. **可复现**（非偶发）？
6. 已留存**正常流程 vs 异常流程的请求响应对比**证据？
7. 动作明确获准、对象受控、无真实资损，且清理或回滚结果已核实？

## 与其他 hunt skill 的链

- 逻辑 + `hunt-race-condition`：支付双花 = 逻辑缺陷 + 并发利用
- 逻辑 + `hunt-idor`：修改他人订单价格 = 越权 + 逻辑
- 逻辑 + `hunt-auth-bypass`：跳过认证步骤 → 直接进入支付确认

## Finding 输出格式

```
### <Title>
- Severity: Critical | High | Medium | Low
- Asset: <业务流程 + 操作接口>
- Reproduction: <异常操作序列 + 参数>
- Impact: <资损类型与量级 / 流程影响>
- Evidence: <evidence/ 正常vs异常流程对比>
- Status: confirmed | inconclusive | blocked | false_positive | out_of_scope
```
