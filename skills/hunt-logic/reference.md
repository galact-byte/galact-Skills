# 业务逻辑验证参考

## 先写规则，再构造变体

| 功能 | 明确的不变量 | 最小对照 |
|---|---|---|
| 金额/数量 | 金额由服务端规则计算、数量范围有效 | 正常订单与一个字段变化后的沙箱订单 |
| 优惠/积分 | 使用资格、叠加规则、单次消费 | 同样初态下的正常使用与重复请求 |
| 流程 | 必须满足前置身份/审批/支付状态 | 合法路径与省略一个步骤的受控副本 |
| 状态机 | 明确允许的转换和最终态 | 正常转换、跳步、逆向和重放 |
| 密码/恢复 | 需要何种重认证、恢复凭据或事务绑定 | 按实际设计比较，不能假定所有重置都必须提供旧密码 |

先确定规则来源，避免把业务允许的赠品、折扣或恢复流程当作漏洞。只在对应动作明确获准、可清理的测试对象上执行；金额小、测试账号或事后回滚不代替许可。

## 金额与状态

以下仅示意字段候选，不是可对真实商户直接提交的载荷：

```json
{"productId": "CONTROLLED_TEST_PRODUCT", "price": 0.01}
{"productId": "CONTROLLED_TEST_PRODUCT", "quantity": -1}
```

核查服务端是否重算总价、绑定折扣资格、校验单位与范围。请求被接受不证明按客户端金额结算；需对照订单、库存、沙箱账本与最终结算状态。支付回调、审批与退款操作需分别取得动作许可。

状态机示例：`draft → pending → approved → executed → archived`。在受控副本上一次省略或重复一个转换，核对权限、响应及后端实际状态。无法恢复同样初态时说明限制，不将两轮不可比结果直接相减。

## 数值边界

- 32 位有符号边界可能是 2147483647，但后端也可能使用更大整数、十进制定点或直接拒绝。不能凭大数就断言溢出。
- 浮点表示差异本身不是资损；按币种最小单位与明确舍入规则对照实际入账。
- 极大数量可能占用库存或消耗资源，只在明确获准的隔离测试中使用。

## 证据与停止

保存预期规则、账号角色、对象初态、正常/变体请求、最终业务 ID 与状态、量化差值、清理结果。UI 提示、HTTP 200、排队受理和理论最大金额都不能代替最终副作用证据。

缺许可/可恢复对象记 `blocked`；规则、状态或因果不明记 `inconclusive`；只有对照证伪时记 `false_positive`。严重度按实际可达影响评定，不将显示异常或沙箱差额写成真实资损。
