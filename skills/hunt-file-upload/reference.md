# 文件上传验证参考

## 分层观察

| 层级 | 记录 | 不能直接推导 |
|---|---|---|
| 接收 | 原始文件名、声明 MIME、实际字节、响应 | 接收成功不等于允许执行 |
| 存储 | 对象 ID、重命名、存储位置、权限 | 已存储不等于公开或可执行 |
| 访问 | 最终 URL、身份、Content-Type/Disposition、正文 | 可下载可能是业务预期 |
| 解析 | 处理组件/版本、转换前后内容、可验证结果 | 扩展名或 Magic Bytes 不证明处理器已执行 |
| 边界 | 对象授权、受控路径、预期允许类型 | 绕过前端校验不等于后端漏洞 |

先用带唯一标记的普通文本验证上传与取回链，记录内容哈希和清理方式。检查 MIME、扩展名和文件头时一次只改一个因素，避免将多个变化的结果混为同一原因。

## 类型与处理器

`.php`、`.phtml`、`.aspx`、`.jsp` 等是否执行，取决于实际 Web handler、存储目录、映射及版本配置；不能把一张扩展名表当成通用执行清单。Python/Ruby 文件通常也需要 CGI 或其他明确执行路径。

Magic Bytes 只提供格式线索，不能证明文件完整合法或无主动内容。图片重编码、文档转换、压缩解包与杀毒扫描属于不同处理链，逐项取证。

仅在脚本执行验证明确获准时使用固定算术或静态标记。避免 `phpinfo()`，它可能泄露配置、环境和凭据；不需要 WebShell 来证明解析。

## 解析差异的前提

Apache 多扩展名、旧 IIS 分号/路径行为、Nginx 与 FastCGI 路径处理都依赖具体版本和 handler 配置。`cgi.fix_pathinfo=1` 单独不足以证明任意文件按 PHP 执行；现代默认配置与历史漏洞示例可能不同。

记录实际栈、版本、请求路径和解析结果；未知时写未知，不套旧教程直接报漏洞。多格式文件、HTML/SVG 渲染和 XSS 验证需要相应内容许可，禁止把主动内容上传给真实用户。

## 路径与覆盖

仅对明确获准、可清理的测试目录验证文件名规范化、解压穿越或同名覆盖。不要用系统配置、计划任务、现有源码或用户文件作“最小证明”。记录对象、初态、备份/清理与最终结果。
