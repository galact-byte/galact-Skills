# Skill 分发约定

## 范围与入口

新增或修改 `skills/` 文档、辅助脚本与分发校验时适用。主验证入口为 `bash tests/run_tests.sh`，分发专项入口为 `python -m unittest discover -s tests -p test_distribution.py -v`；非零退出表示失败。

## 目录契约

- 每个顶层 Skill 目录只保留一个 `SKILL.md`，不嵌套第二份同名入口。
- 必需参考文件随本目录提供，使用可解析的相对 Markdown 链接。
- 不依赖宿主私有知识库、规则或路径配置；外部工具只能作为可选能力，缺失时说明阻塞。
- 本库不附带的可执行脚本不得出现在可直接运行的命令中。
- `_toolbox.md` 随完整分发包提供；单独复制 Skill 后不是运行前提。

## 校验与错误

`distribution_errors(root: Path) -> list[str]` 返回相对文档路径与具体原因：私有依赖、失效本地链接、嵌套入口。输出路径统一使用 `Path.as_posix()`，保证 Windows 与 Linux 的诊断和断言一致。整库分发检查失败时，测试主入口必须退出非零，即使各 Skill 的基础检查均通过。

- 正例：`[参考](reference.md)` 且文件随目录存在。
- 基线：官方 HTTPS 链接与文档内锚点不按本地文件校验。
- 反例：指向宿主未提供文件、缺失参考或重复入口。

## 必需验证

分发测试须同时覆盖正常相对链接、外部 URL、失效本地链接、私有依赖与嵌套入口，防止空扫描仍全绿。发布前运行完整入口和 `git diff --check`，按发布工作流的实际 ZIP 构建逻辑检查解包内容。

静态结构、语法与导入检查不等于真实漏洞可利用或模型行为验证。未进行目标测试时明确说明，不能用场景文字审阅替代实际模型测试。

## 发布附件与跨平台换行

远端附件须对照发布标签的 Git blob 逐字节核验；本机 Windows 工作树可能使用 CRLF，而 Linux 发布工作流检出的文本使用 LF。不能直接用工作树哈希断言远端附件被改动，也不能将所有附件统一换行后跳过字节检查。

```python
expected = subprocess.check_output(["git", "show", f"{tag}:{relative_path}"])
assert archive.read(relative_path) == expected
```

同时核对附件完整路径集合、重复条目、Skill 入口数量、许可文件和发布正文。仅工作树换行不同且附件匹配 Git blob 时通过；缺失、多余、重复文件或任何字节差异均失败，并保留附件与日志排查。ZIP 容器本身可能因时间戳或压缩环境不同而哈希不同，不替代逐文件核对。

## 证据与判定

不能将缺许可、缺工具、未复现与已证伪都写为同一结论。DNS 悬挂不等于可接管，JNDI 出网不等于 RCE，HTTP 200 不等于业务动作成功。工具名、参数与版本前提以现场帮助及官方资料为准。
